# Runtime Handoff Contracts v1

This document describes the small runtime handoff contracts added for real-project PlanToDelivery trial readiness.

## Provider Doctor: `p2d-provider-doctor/v1`

Generated by `diagnose_provider_registry(project_root, required_capabilities=[...])` and surfaced through:

```bash
python .agents/skills/plantodelivery/scripts/p2d_doctor.py \
  --project-root . \
  --required-capability visual_implementation \
  --json
```

Required fields:

- `schema`: `p2d-provider-doctor/v1`
- `ok`: boolean
- `providers`: sorted provider IDs discovered from the registry
- `capabilities`: map from capability to selected provider metadata
- `required_capabilities`: normalized required capability list
- `missing_capabilities`: required capabilities absent from registry
- `violations`: actionable errors; missing required capabilities use `missing_required_capability`

## Project Aliases: `p2d-project-aliases/v1`

Used to resolve stable project nicknames without broad filesystem search.

```json
{
  "schema": "p2d-project-aliases/v1",
  "aliases": {
    "ruoshui": "/mnt/c/Users/imjzq/Projects/ruoshui"
  }
}
```

Runtime helpers:

- `write_project_alias_registry(path, aliases={...})`
- `load_project_alias_registry(path)`
- `resolve_project_alias(value, registry_paths=[...])`

Unknown aliases raise `KanbanContractError`; callers must not silently guess.

## Approval Packet: `p2d-approval-packet/v1`

Created when a provider result validates but requires user review before completion.

```bash
python .agents/skills/plantodelivery/scripts/p2d_enforce.py \
  --project-root . \
  approval-packet \
  --task-envelope project-state/kanban/tasks/TASK/task-envelope.json \
  --result-manifest project-state/kanban/tasks/TASK/result-manifest.json \
  --output project-state/kanban/tasks/TASK/approval-packet.json
```

Required fields include:

- `schema`: `p2d-approval-packet/v1`
- `task_id`, `capability`, `provider`
- `status`: always `review`
- `requires_user_decision`: always `true`
- `review_prompt`
- `changed_files`, `produced_artifacts`, `evidence`, `debts`, `blockers`
- `approval_options`: `approve`, `request_changes`, `block`

The builder rejects non-review results and task/result mismatches.

## Resume Snapshot: `p2d-resume-snapshot/v1`

Created at cold-start/checkpoint boundaries to resume without relying on chat context.

```bash
python .agents/skills/plantodelivery/scripts/p2d_enforce.py \
  --project-root . \
  resume \
  --output project-state/kanban/resume-snapshot.json
```

Fields:

- `schema`: `p2d-resume-snapshot/v1`
- `project_root`, `state_root`
- `counts_by_status`
- `review_tasks`, `blocked_tasks`, `running_tasks`, `next_ready_tasks`
- `resume_actions`

Action ordering is deterministic: review packets first, then blockers, running inspection, and ready dispatch.
