# Change Control

Use this file whenever new ideas, requirement changes, or scope pressure appear after planning has begun.

## Core Principle

New ideas do not interrupt current execution by default.

Default route:
- capture
- classify
- defer unless truly necessary

## Backlog Categories

Use four buckets:
- must-handle-now
- next-milestone
- future-idea
- not-doing

This prevents every new thought from becoming live scope.

## Freeze Windows

Scope freezes by default at:
- `milestone-plan`
- `execution`

During freeze, only allow changes that:
- unblock progress materially
- fix invalid acceptance assumptions
- address severe risk
- repair wrong planning facts

## Escalation Triggers

Formally escalate when change affects:
- project goal
- stack choice
- milestone acceptance
- core data model
- permissions/security boundaries
- core UI structure
- key external dependencies
- validity of the active plan

## Change Request Discipline

Major changes should use a written change request.

Document:
- what changes
- why now
- impact
- risk
- whether spec must reopen
- whether plan must reopen
- whether it should be deferred or rejected

## Efficiency Rule

The orchestrator should recommend defaults for low-level decisions so planning does not stall, but should resist mid-execution scope creep.

## Anti-Patterns

Do not:
- absorb every better idea into the active milestone
- reopen planning casually during execution
- hide change impact
- treat scope freeze as advisory only
